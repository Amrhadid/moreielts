# MoreIELTS audit — 29 October 2026

Scope: the live platform (moreielts.com, built from `main`), its shared
Supabase project (`nlsuvapjkznatczghvay`, `ielts_*` objects), the content in
the database, and the learner and admin journeys. The site itself could not
be fetched from this environment (network policy), so the UI review was done
on a local production build of `main` (fc3fbdb) with Playwright screenshots at
390px and 1366px, light and dark, plus the Arabic toggle.

Health of the code: CI on `main` is green; locally `npm run build`,
`npm run typecheck` and `npm test` (139 tests) all pass.

## 1. What is actually live

| Area | State |
|---|---|
| App | TanStack Start on a Cloudflare Worker, built from `main`. Google-only sign-in shared with MoreTOEFL. |
| Access model | Premium-only. No free tier, no trial, no price shown. Premium is granted by access codes that the owner sends over WhatsApp (`/pricing` → WhatsApp → code → redeem). Stripe checkout exists in the repo but is not deployed and is hidden behind `VITE_STRIPE_ENABLED`. |
| Content | 10 published forms: 4 mock exams (Academic 1–2, GT 1–2) and 6 practice forms. 940 questions, every Listening/Reading question has an explanation, all 40 listening parts narrated (4–6 min each, 64 kbps TTS), reading passages 850–875 words (GT sections 210–300). 17 public strategy guides, 16 vocabulary topics × 25 words with Arabic. |
| Features | Dashboard, study plan, practice sets (5 per skill, AI-corrected via the shared `claude-completion` function), drills by question type, Leitner mistake notebook, writing lab with rewrite loop, vocabulary + flashcards, mock test player (server timing, play-once audio, recorded speaking), background AI grading (Claude + ElevenLabs transcription), results with transcripts, admin (forms, students, codes, analytics). |
| Backend | 14 migrations applied. Four Edge Functions deployed (`ielts-submit-attempt`, `ielts-drill`, `ielts-grading-worker`, `ielts-generate-audio`) as one-line loaders that import a bundle from jsDelivr pinned to commit `c720067`. Sources have not changed since, so the pin is current. Vault keys and the minute cron (`ielts-grading-sweep`, 2 880 successful runs in 48 h) are in place. |

### Usage since launch (21 October)

| Metric | Value |
|---|---|

| Access codes generated | 0 |

The 800 accounts in the project are MoreTOEFL's. Nothing on the IELTS side
has been exercised by a real learner, and the mock → grading → results
pipeline has **never run in production**. That is the first thing to fix:
not a feature, a proof that the product works end to end.

## 2. Findings

Severity: **P0** blocks selling, **P1** hurts every learner, **P2** polish.

### P0 — must do before any marketing push

1. **Unverified production pipeline.** No attempt has ever been submitted.
   Grading depends on `ANTHROPIC_API_KEY`, `ELEVENLABS_API_KEY`, the Vault
   worker key, pg_net reaching the worker, and the jsDelivr bundle. Run one
   full mock as the admin (admins count as Premium) and watch
   `ielts_grading_jobs` go pending → done; then add an admin **System health**
   card so this is visible at a glance (pending/failed jobs, last worker run,
   which secrets the worker can see).
2. **Every answer key is public.** The repository is public (it has to be
   for the jsDelivr loader trick), and `supabase/seed.sql`,
   `scripts/seed-content/**` and the listening scripts contain the accepted
   answers for all 10 forms. The "a candidate never receives an accepted
   answer" guarantee is defeated by a GitHub search. Deploy the bundled
   functions directly (`supabase functions deploy` with `_dist`), drop the
   jsDelivr loaders, then make the repo private (or move the content to a
   private repo).
3. **Mandatory, Arabic-only onboarding modal.** Every signed-in learner,
   including an English-interface user who only wants to look around, is
   blocked by an Arabic form asking for name, nationality and WhatsApp
   before they have seen anything or bought anything. There is no skip and
   no English version. Localise it, make it skippable once, and ask for the
   WhatsApp number at the moment it is needed (getting a code).
4. **`/pricing` is a dead end with no price.** The page renders without the
   header, sidebar or footer (it does not use `AppShell`), so the only way
   out is the browser back button. It never says what Premium costs or how
   long a code lasts; the only action is "message us on WhatsApp". Add the
   shell, the prices for the 30/90/180-day codes, what happens after you
   message, and an FAQ.
5. **Nothing on the landing page converts.** No price, no free sample, no
   screenshots of the player or feedback, no testimonials, no Arabic copy,
   footer About/Privacy/Terms are `href="#"`, and the closing CTA says
   "Sign in or sign up" when sign-up does not exist (Google only). The
   "Start a drill" button on every public guide leads to sign-in and then a
   lock screen. Give visitors one free thing to do (a 10-question placement
   test or one free drill per type), show the price, and link real
   Privacy/Terms pages (Google's OAuth consent screen also needs them).
6. **GitHub default branch is stale.** The repository's default branch is
   `claude/moreielts-practice-app-jkmoex` (August), while production builds
   from `main`. Open PRs #2 and #7 target the stale branch. Set `main` as
   default and close or rebase those PRs.

### P1 — bugs and friction in the learner journey

7. **Mock exam order is not enforced.** `/mock` lists "Open section →" links
   that drop the `?form=` parameter, so a learner can start Reading on the
   default form (Academic Mock 1) before Listening, and on a different exam
   than the one they chose. The page promises "sections run in the official
   order". Remove those links and have `ielts_start_section` refuse a
   section whose predecessor has not been submitted.
8. **Variant is never asked.** A General Training candidate is shown
   Academic Task 1 charts in the writing lab, Academic reading drills, and
   the Academic default form. Ask Academic vs GT in onboarding, store it on
   `ielts_learners`, and filter mocks, drills, writing prompts and the study
   plan by it.
9. **Leaving a test is silent.** The player header's "← Exit" link has no
   confirmation; the server clock keeps running and the learner may not
   know the section is still live. Add a confirm dialog and a "resume"
   banner on the dashboard with the time left.
10. **Speaking player has no pre-flight.** The microphone permission is
    requested only when the first "Record" is pressed; the Part 2 recorder
    auto-starts (surprising); a failed upload shows one line of red text and
    the recording is gone when the page changes. Add a mic check before the
    section starts, keep the blob until the upload succeeds, and retry.
11. **Listening on a phone.** The audio and questions are separate tabs, so
    the learner presses Play then has to find the Questions tab. Switch to
    the questions pane automatically when playback starts and keep a slim
    audio status bar visible. `audio_duration_ms` is null for every part, so
    the progress bar has no total until metadata loads; fill it from the
    MP3s at seed time.
12. **New Premium learner sees an empty dashboard.** Two band cards that both
    say "—", an empty chart, "No attempts yet", and a 7-task plan. Replace
    the empty state with a three-step start (placement → first drill →
    first mock) and merge the "Estimated band" and "Predicted band" cards.
13. **Admins see the lock banner.** The dashboard checks `profile.tier`
    instead of `isPremium`, so the admin is told their exams are locked.
14. **Drill dead ends.** The error copy for `no_free_content_for_type`
    talks about "free sets" and "Upgrade to Premium" on a Premium-only site;
    the Speaking tab says "practised in the full mock tests" although
    `/practice/speaking` exists. Point both at the right place.
15. **Results page stops at the numbers.** "Grading failed — contact
    support" has no action; there is no "drill your weakest types" or "book
    the next mock" step. Add next-step cards and a retry for failed jobs
    (admin side too).
16. **Arabic interface is half done.** About 45 strings are translated (nav
    and page titles); every page body, every error, the onboarding and the
    pricing page stay English, so the Arabic toggle produces a mixed page.
    Either finish the learner-facing chrome in Arabic or hide the toggle
    until it is done. Given the audience (Arabic onboarding, Arabic
    vocabulary, Saudi/Egypt first), finish it.
17. **No re-engagement.** No email or WhatsApp reminder exists for IELTS
    learners; the weekly plan email in MoreTOEFL is not wired for IELTS.
    Reuse the Brevo sender for a weekly "your plan this week" email.

### P2 — polish, admin and hygiene

18. Admin Students table ignores the WhatsApp, nationality and onboarded
    columns the RPC already returns, and has no way to grant or revoke
    Premium directly, nor a per-learner view (attempts, essays, drills).
19. Admin has no content-health view (forms without audio/explanations,
    forms per variant) and no way to retry a failed grading job.
20. `/results` says "Every practice set and mock test" but lists only mocks;
    drills and essays live on other pages. A single "Progress" page would
    serve better.
21. `scripts/__pycache__/.ielts-rename.cpython-313.pyc` is committed; a
    stale `TODO(backend)` remains in `src/types/content.ts`; the README still
    documents `grade-writing`/`upload-url`/R2 as if deployed.
22. Security advisor flags `ielts_questions_public` as a SECURITY DEFINER
    view (by design, but worth replacing with an RPC so the linter is
    clean) and several MoreTOEFL functions callable by `anon`.
23. Service worker caches navigations, so the first load after a deploy can
    show the previous page shell; bump `VERSION` per build.
24. Practice AI grading goes through `claude-completion` at the function's
    default temperature (1.0), so the same essay can get different bands on
    two runs; pass `temperature: 0` like the Edge graders do.
25. Dark mode works but `--color-brand-100`/`200` on dark are used as text
    tints in a few badges with low contrast; check with the a11y pass.

## 3. How a learner uses it today, and where they fall

1. Lands on the homepage, sees "Get Premium access" with no price.
2. Signs in with Google (only option).
3. Is blocked by an Arabic form for name, nationality and WhatsApp.
4. Reaches a dashboard full of "—" and a yellow "locked" banner.
5. Goes to `/pricing`, finds no price and no navigation, and is sent to
   WhatsApp. Conversion now depends on how fast the owner replies.
6. Gets a code, redeems it, and is back on the empty dashboard with no
   "start here".
7. Chooses a mock, may open sections out of order, sits a 2 h 45 m exam
   with a silent exit link, records speaking without a mic check.
8. Waits on the results page; if grading fails there is nothing to do.

Fixing items 1–12 turns this into: land → see price and a free placement
test → sign in → pick Academic/GT → see a plan → pay/redeem → guided first
drill → first mock → results that point to the next drill.
